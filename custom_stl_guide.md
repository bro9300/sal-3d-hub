# 🧊 Інструкція з синхронізації та додавання 3D-моделей (.STL) у каталозі «3D САЛ — Степанський ліцей»

У цій версії платформи повністю вирішено проблему синхронізації 3D-файлів (`.stl`, `.obj`, `.3mf`, `.step`) між пристроями, `localStorage`, GitHub Pages та хмарною базою **Firebase Realtime Database**.

---

## 🔧 Що було виправлено в системі синхронізації 3D-файлів

1. **Відокремлення важких `.STL` файлів від основного масиву `products` (`__CLOUD_STL__:{id}`)**:
   - Раніше прикріплений `.STL` файл кодувався в Base64 і записувався безпосередньо в поле `stlUrl` всередині масиву `products`. Це призводило до переповнення ліміту браузера `localStorage` (`QuotaExceededError`, ліміт 5 МБ) та переривання запитів `firebaseFastWrite("products")` за таймаутом (7 секунд).
   - Тепер каталог `products` зберігає лише легкий маркер `__CLOUD_STL__:{id}` (весь каталог важить **~15 КБ** і синхронізується за **100–200 мс**), а самі бінарні дані `.STL` зберігаються локально в **IndexedDB** (`sal_3d_files_db_v1`) та синхронізуються у виділений вузол Firebase `stl_files/{productId}` чанками по **180 КБ**.

2. **Автоматична оптимізація `.STL` (ASCII → Binary STL + спрощення сітки)**:
   - Під час вибору файлу в адмін-панелі або у формі індивідуального замовлення система автоматично конвертує текстові (ASCII) `.STL` у компактний бінарний формат та оптимізує надто важкі полігональні сітки (>35 000 трикутників), зменшуючи розмір файлів у **3–15 разів** без втрати візуальної якості.

3. **Усунення нескінченного циклу перезапису Firebase (`rawSize > 250000`) та збереження базових моделей (`DEFAULT_STL_MAP`)**:
   - Додано словник базових моделей `DEFAULT_STL_MAP`, завдяки чому хмарна синхронізація ніколи не затирає посилання на стандартні 3D-моделі в папці `models/`.
   - Усі 6 базових моделей (`headphone_stand.stl`, `phone_stand_slotted.stl`, `toothbrush_holder.stl`, `fpv_shield.stl`, `gopro_mount.stl`, `fpv_arm_protector.stl`) присутні у папці `models/` та додатково вбудовані у стисненому Gzip-архіві `BUILTIN_STL_ARCHIVE` для миттєвої роботи навіть офлайн.

4. **Хмарна синхронізація клієнтських 3D-файлів у замовленнях (`order_files/{orderFileId}`)**:
   - Коли замовник прикріплює власний 3D-файл у вікні «Індивідуальний 3D-друк», файл зберігається в IndexedDB (не зникає після оновлення сторінки), відправляється у Telegram-бот майстерні та вивантажується у Firebase (`order_files/{orderFileId}`).
   - В адмін-панелі у блоці **«Останні замовлення (Firebase Realtime DB)»** біля кожного такого замовлення з'являються кнопки **«Завантажити»** та **«3D-огляд»**.

## 🚀 Спосіб 1. Додавання або заміна `.STL` через Адмін-панель (Рекомендовано)

1. Натисніть на іконку шестерні ⚙️ у верхньому правому куті сайту та увійдіть в адмін-панель.
2. У формі **«Додати товар до каталогу»** (або під час редагування товару кнопкою **✏️ Редагувати**) натисніть поле **«3D-модель (.STL файл)»** і оберіть файл `.stl` зі свого комп'ютера чи смартфона.
3. Система автоматично оптимізує модель і покаже її розмір у статус-барі. Ви можете одразу натиснути кнопку **«👁️ Тест 3D»**, щоб перевірити модель на інтерактивному столі 3D-принтера.
4. Натисніть **«Опублікувати товар»** або **«💾 Зберегти зміни»** — модель миттєво збережеться в IndexedDB та синхронізується з Firebase (`stl_files/{id}`) для всіх відвідувачів сайту.

## 📁 Спосіб 2. Статичні файли у папці `models/` (для GitHub Pages)

У папці `models/` репозиторію розміщені оптимізовані бінарні `.STL` моделі:

- `models/headphone_stand.stl` — Настільна підставка для навушників «Gamer Pro» (ID: `5`)
- `models/phone_stand_slotted.stl` — Підставка для смартфона з гербом ліцею (ID: `7`)
- `models/toothbrush_holder.stl` — Органайзер для зубних щіток та пасти (ID: `11`)
- `models/fpv_shield.stl` — Захист пропелерів та антени для навчальних FPV-дронів (ID: `23`)
- `models/gopro_mount.stl` — Кріплення екшн-камери GoPro / RunCam на FPV-раму (ID: `24`)
- `models/fpv_arm_protector.stl` — Комплект захисту променів та моторів FPV-дрона 4 шт. (ID: `25`)
